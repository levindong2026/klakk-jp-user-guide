# macOSのInput Monitoringを後から取り消し、再び許可するときの確認手順

> 本稿は有料機能を含むmacOSアプリ「Klakk」の開発者が、現行実装をもとに作成した権限運用ガイドです。自社製品へのリンクを含みます。macOSの表示名や手順はOSバージョンと言語設定で変わる場合があります。

Input Monitoring（入力監視）は、一度許可したら永久にそのままにする必要はありません。macOSのシステム設定から後で取り消し、必要になったときに再び許可できます。

Klakkでは、ほかのアプリを使っている間にもキーが押されたタイミングでローカルの打鍵音を再生するために、この権限を使います。入力した文章を編集するための権限ではありません。

ここでは、権限を取り消す操作、アプリ側で起きること、再許可後に確認する順序を分けます。

## 1. 取り消す前に現在のアプリを確認する

Input Monitoringの一覧には、同じ名前の項目や、以前使っていた別ビルドが残る場合があります。変更前に次を確認してください。

- 現在使っているのがMac App Store版、署名済み配布版、Xcodeから実行した版のどれか
- メニューバーに表示されているKlakkが現在の対象か
- 作業中の文書を保存しているか
- オンライン会議中ではないか

権限を取り消しても入力した文書が消える操作ではありませんが、Klakkの打鍵音と設定したグローバルホットキーは動作しなくなります。

## 2. システム設定から取り消す

macOSの一般的な経路は次の通りです。

1. **システム設定**を開く
2. **プライバシーとセキュリティ**を選ぶ
3. **入力監視**を開く
4. 対象のKlakkを確認する
5. スイッチをオフにする

OSの指示でアプリの終了や認証が必要になった場合は、その画面の説明を確認してください。似た名前の別アプリや別ビルドをまとめて変更せず、対象を一つずつ確認します。

## 3. 取り消した後にKlakkで起きること

現行実装では、キーイベントの監視中に権限状態を定期確認しています。権限が失われたことを検知すると、次の処理を行います。

- Event Tapを無効化して破棄する
- RunLoop Sourceを取り外す
- 押下中として保持していたキー状態を消去する
- 修飾キーの前回状態を消去する
- メニューを更新して権限警告を表示する
- グローバルホットキーの監視も停止する

監視中の確認間隔は現行コードで約2秒です。OSの権限状態が変わるタイミングとアプリの確認タイミングは同時とは限らないため、「スイッチを切った瞬間の1フレーム」まで保証する値としては扱いません。

```swift
if !hasPermission && isMonitoring {
    wasMonitoring = true
    stopMonitoring()
    NotificationCenter.default.post(
        name: .init("KeyboardMonitoringPermissionRevoked"),
        object: nil
    )
}
```

`stopMonitoring()`はEvent Tapを止めるだけでなく、押下状態も初期化します。権限を失った間に`keyUp`を受け取れず、再開後もキーが押されたままだと誤認しないためです。

## 4. 再び許可する

再許可も同じ**入力監視**の画面で対象のKlakkをオンにします。

現行実装は、権限を失う前に監視していたことを記録し、権限が戻ったことを定期確認します。ただし、権限が戻れば無条件に打鍵音を再開するわけではありません。Klakk自体が有効になっている場合だけ監視を開始します。

```swift
if hasPermission && !isMonitoring && wasMonitoring {
    wasMonitoring = false

    if AppSettings.shared.isKlakkEnabled {
        startMonitoring()
    }
}
```

これは、利用者が意図的にKlakkを無効にしている状態を、権限変更だけで勝手に有効化しないための境界です。

再許可を検知すると、メニューから権限警告を外し、グローバルホットキーが設定済みならその監視も再開します。

## 5. 再許可後に音が出ない場合の確認順序

権限以外の原因と混ぜず、次の順で確認します。

1. システム設定の入力監視で対象のKlakkがオンか
2. メニューバーでKlakk自体が有効か
3. 音量が0になっていないか
4. 選択したサウンドパックが読み込まれているか
5. macOSの出力先が意図したAirPods、スピーカー、USB DACか
6. 別ビルドのKlakkへ権限を付けていないか
7. OSが再起動を求めている場合、その案内に従ったか

権限表示が正しいのに反応しない場合は、Klakkを終了して再起動し、もう一度メニューと出力先を確認します。権限を何度もオン・オフする前に、現在実行中のアプリと一覧の項目が同じかを見直してください。

## 6. 使わなくなった場合

Klakkを無効にする、アプリを終了する、Input Monitoringを取り消す、アプリを削除する、という操作はそれぞれ意味が異なります。

- 一時的に音だけ止める：Klakkを無効にする
- 常駐も止める：Klakkを終了する
- キーイベントへのアクセスを止める：Input Monitoringを取り消す
- 今後使わない：アプリを終了し、権限を取り消してから削除する

アプリ削除後もmacOSの権限一覧に古い項目が残る場合は、システム設定から整理できます。

## プライバシーと製品限界

Klakkの現行実装は、キーの押下・解放、物理キーコード、修飾キー状態を端末上で処理し、対応する音を選びます。入力した文章、パスワード、個々のキーコードやキー操作の並びを保存・送信する設計ではありません。

一方で、アプリ起動、設定、権限状態、サウンドパック、一定単位にまとめた利用回数などの解析イベントは、製品改善のため別に扱います。最新の範囲は[日本語プライバシーポリシー](https://tryklakk.com/ja/privacy/)で確認してください。

Klakkが変えるのはMacから追加して再生する音です。実物のキーボードの物理音や打鍵感は変えません。ASMRや集中の感じ方には個人差があり、ADHDを含む症状を診断、治療または改善する医療製品ではありません。
