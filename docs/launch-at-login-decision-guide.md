# Macのメニューバーアプリを「ログイン時に起動」するか決めるチェックリスト

> 本稿は有料機能を含むmacOSアプリ「Klakk」の開発者が、現行のログイン項目実装をもとに作成した利用ガイドです。自社製品へのリンクを含みます。

メニューバーアプリは、Macへログインした直後から使えると便利です。一方で、たまにしか使わないアプリまで毎回起動すると、何が常駐しているのか分かりにくくなります。

Klakkの「ログイン時に起動」は初期状態でオフです。利用者が初回案内または一般設定で明示的にオンにした場合だけ、macOSのログイン項目として登録します。

「便利そうだからオン」ではなく、次の条件を確認して決めてください。

## 1. 毎日使うMacか

次のような使い方なら、ログイン時起動が役立ちます。

- 毎日同じMacで文章を書く、コードを書く
- 打鍵音を使う時間帯がほぼ決まっている
- メニューバーからすぐオン・オフしたい
- ログイン後に毎回アプリを探して開く手間を減らしたい

一方、週に一度だけ使う、音を試すときだけ開く、共有Macを使う場合は、必要なときに手動で起動する方が状態を理解しやすくなります。

## 2. 「アプリが起動する」と「音が鳴る」を分ける

ログイン項目は、Macへログインしたときにアプリを起動する設定です。次の状態とは別です。

- Klakk自体が有効か
- 音量が0でないか
- サウンドパックが読み込まれているか
- Input Monitoringが許可されているか
- 出力先がAirPods、スピーカー、HDMI、USB DACのどれか

ログイン時起動をオンにしても、Input Monitoringの権限が自動的に付与されるわけではありません。権限を取り消した状態なら、アプリが起動してもキー入力へ反応できません。

反対に、ログイン時起動をオフにしても、必要なときにKlakkを手動で起動して使えます。

## 3. 共有Macでは誰のセッションか確認する

会社、学校、家族で使うMacでは、ログイン項目は利用者ごとの運用と管理ポリシーに影響されます。

- 自分専用のmacOSユーザーであるか
- 組織の管理者がログイン項目を制限していないか
- 別の利用者が同じ音設定を望んでいるとは限らない
- 会議室Macや一時利用端末へ常駐させる必要があるか

自分の判断だけで常駐アプリを追加できない環境では、組織のルールを優先してください。

## 4. 初回案内ではチェックが入っていないことを確認する

Klakkの現行実装では、初回のInput Monitoring案内に「ログイン時に起動」のチェック項目があります。初期状態はオフです。

Input Monitoringを開く操作と、ログイン時起動へ登録する操作は別々の同意です。権限案内を進めるために、ログイン時起動までオンにする必要はありません。

必要なら後から一般設定で変更できます。

## 5. macOS 13以降ではServiceManagementを使う

現行実装は、macOS 13以降の`SMAppService.mainApp`を使ってメインアプリを登録・解除します。

```swift
if enabled {
    try SMAppService.mainApp.register()
} else {
    try SMAppService.mainApp.unregister()
}
```

登録に失敗した場合、Klakkは設定トグルを以前の状態へ戻し、変更できなかったことを表示します。「アプリ内のスイッチがオンに見える」だけで成功と判断しない設計です。

OS側の状態は、macOSのシステム設定にあるログイン項目からも確認できます。表示名や場所はmacOSのバージョンと言語によって変わる場合があります。

## 6. オンにした後の確認

設定を変えた直後は、次を確認します。

1. Klakkの一般設定で「ログイン時に起動」がオンか
2. macOSのログイン項目にKlakkが表示されるか
3. Macへ再ログインした後、メニューバーにKlakkが現れるか
4. Input Monitoringが引き続き許可されているか
5. Klakk自体が有効か
6. 出力先と音量が意図した状態か

ログイン直後に音が出ない場合、「ログイン項目の登録失敗」「権限なし」「Klakkが無効」「出力先の変更」を分けて調べます。

## 7. オフにしたいとき

Klakkの一般設定で「ログイン時に起動」をオフにすると、現行実装は`SMAppService.mainApp.unregister()`を呼びます。

これは次回以降の自動起動を止める設定です。現在動いているKlakkをその場で終了する操作、打鍵音だけを一時停止する操作、Input Monitoringを取り消す操作とは異なります。

目的に合わせて選びます。

- 今だけ音を止める：Klakkを無効にする
- 現在のアプリも止める：Klakkを終了する
- 次回ログイン時の自動起動を止める：「ログイン時に起動」をオフにする
- キーイベントへのアクセスを止める：Input Monitoringを取り消す
- 今後使わない：上記を確認してからアプリを削除する

## 8. アプリを移動・再インストールした後

別ビルド、別の署名、App Store版と開発版が混在すると、ログイン項目やInput Monitoringの対象を取り違える可能性があります。

再インストール後に動作が違う場合は、現在起動しているKlakkの場所と、macOS側に表示されている項目を確認してください。古い項目を残したまま新しい項目も登録するより、現在使う版を一つに絞る方が確認しやすくなります。

## プライバシーと製品限界

Klakkは、キー入力に同期してローカルの打鍵音を再生するためInput Monitoringを使います。ログイン時起動をオンにすること自体が、追加の入力データを保存する設定ではありません。

入力した文章、パスワード、個々のキーコードやキー操作の並びを保存・送信する設計ではありません。アプリ起動、設定変更、権限状態などの利用状況イベントとは分けて扱います。最新の説明は[日本語プライバシーポリシー](https://tryklakk.com/ja/privacy/)で確認してください。

Klakkが変えるのはMacから追加して再生する音です。実物のキーボードの物理音や打鍵感は変えません。ASMRや集中の感じ方には個人差があり、ADHDを含む症状を診断、治療または改善する医療製品ではありません。
